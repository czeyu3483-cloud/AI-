# 产品备忘录 · 仿真 AI 模拟面试官

**产品**：浏览器内可跑的研发岗模拟面试 Demo（默认校招/实习深度预期）  
**闭环**：脱敏简历 → 语音对练（业务面）→ 结构化复盘 / PDF  
**定位**：比「对着 ChatGPT 自问自答」更像一场会被追问、会被质疑的真实业务面。

**当前主路径（业务面）**：自我介绍 → 简历深挖×2 → 学科专业题 → 编程题 → 终局复盘（含一致性汇总与编程评价）。

---

## 1. 目标用户与核心痛点

**目标用户**：正在准备大厂/互联网校招或实习研发一面的本科生与近期实习候选人。他们通常有一份写满项目的简历，却很少有机会被「像面试官一样」压着问细节。

本轮迭代把产品负责人当作持续访谈对象，结合试跑与改需求，沉淀出几条比「找不到人对练」更可执行的痛点：

1. **没有真实感的追问者**。同学互问或自己对着模型练，题往往一轮一答；不会抓住「你简历写了 P95 从 800ms 到 200ms」继续问口径、验证方式与个人边界。
2. **简历与口述不一致几乎不被挑战**。候选人夸大职责、指标或技术栈时，通用对话助手倾向于顺着写；真实面试官会停下来核实，甚至因诚信问题提前结束。
3. **空泛回答被轻轻放过**。说「负责后端」「做了优化」却给不出步骤与结果时，需要一次短探后换题并打标，而不是无限追问「再详细一点」。
4. **语音交互本身会破坏沉浸感**。自动拾音误触发、人像乱晃、开场自称「模拟/压力面」、答完不知何时提交——都会让人立刻出戏。
5. **反馈若含「流利度」等与内容无关的维度，可信度下降**。候选人更想知道：技术深度够不够、项目是否站得住、下一句该怎么改。
6. **编程环节若当场宣判对错，会打断面试节奏**。产品保留编程题，但评价只进终局复盘；开场与主 UI 不宣传「可以不编程」。

因此 MVP 收敛为：**研发岗 · 压力面风格 · 业务面轨道**——用状态机 + 简历锚定题，把「被追问 / 被质疑 / 拿到可执行复盘」做成一条可复现主路径。

## 2. 产品设计说明

### 2.1 业务面流程（当前）

共 **自我介绍 + 约 4 主问题**（配置 `questionsPerSession: 5`）：

| 环节 | 内容 | 关键口径 |
| --- | --- | --- |
| 0 · 自我介绍 | 「先做个简单的自我介绍…」 | 不完整最多 **1 次短探**后必须推进；全文合并落盘 `selfIntroText` 供后文比对；每答全场一致性核查 |
| 1–2 · 简历深挖×2 | 短前置「我看你的简历，我想问…」 | **不问简历已写清的事实**；追问 **WHY / 规模 / 职责 / 失败与边界** |
| 3 · 学科专业题 | 题库随机：高等代数 / 线性代数 / 概率论 / 数理统计 / 微积分 | **当场不判对错**；终局合理宽松打分 |
| 4 · 编程题 | 编辑器手写 JS 提交 | **当场不宣判对错**；跑测结果仅终局复盘展示 |

开场口语**不告知题目数量**；也**不**说「可以不编程 / 本次先不练」。编程页仅保留极弱出口「继续下一环节」（非主 CTA、开场/主文案不出现）。

### 2.2 全场一致性核查（每答必做）

候选人每次作答、**推进下一题之前**：

1. 抽取本答关键事实（姓名、学校、专业、时间、公司、职位、项目名称、项目角色、技能、GPA、奖项、数字/排名）
2. 对照 **简历全文字段**
3. 对照 **全部历史作答**（逐轮）
4. 对照 **自我介绍**（句/事实级）
5. 高/中严重度不一致 → **立刻打断挑战**（不等到终局）；低严重度（技能）默认可记入列表但不打断
6. 追加到会话耐久列表 `inconsistencies`
7. 等解释后再继续（沿用 pending challenge 流）

| 字段 | 严重度 |
| --- | --- |
| 姓名 / 学校 / 时间 / 公司 / 职位 / 项目角色 / GPA / 数字排名 | high（**立刻打断**；姓名冲突永不 defer 到终局报告） |
| 专业 / 项目名称 / 奖项 | medium（**立刻打断**） |
| 技能 | low（记入列表；默认不打断） |

挑战话术多版轮换；**姓名冲突**固定优先用：「等一下，简历上写的是「张三」，但你刚才说的是「李四」，哪个是对的？」。多问题并列时用「等一下，我发现了几个问题需要澄清：」。

DeepSeek 可用时做抽取+比对；无 Key 时启发式兜底（含简历 `姓名：` 标签与口述「我是/我叫」）。**LLM 不得把高严重度冲突降级为 level4 / 仅记报告**；引擎在自我介绍与后续每答推进前都会再跑本地核查并强制打断。近邻实体（如「前端开发实习」≈「前端实习」）按同一核心实体匹配，避免误打断。终局复盘按严重度（high / medium / low）汇总并给改进建议。

### 2.3 面试官政策（硬口径）

1. **不告知题量**：开场白 / TTS / 进度条均不得预告题数。
2. **话术随机化**：过渡、追问、纠偏、一致性挑战等同义多版轮换。
3. **最多补充一次**：不完整作答最多一次补充，然后必须进入下一题。
4. **严格核查一致性**：见 2.2；冲突立刻打断，并记入终局复盘。
5. **跑题及时纠正**：打断纠偏一次后仍偏则软换题。
6. **专业问题与编程均不当场判对错**：对错与跑测结果只进终局报告。

### 2.4 简历接地气提问（示例）

**宜问（短前置 + 挖 WHY / 规模 / 职责）**

- 「我看你的简历，我想问：做『校园二手交易平台』时为什么选 Next.js，而不是 Vue？数据量大概多大？」
- 「我看你的简历，我想问：围绕『监控告警中台』，哪个模块是你个人真正负责的？」

**不宜问（复述已写事实 / 长篇铺垫）**

- 「我结合你的自我介绍以及简历里的……」（过长前置）
- 「你这个项目用了什么框架？」（简历已写清时）

### 2.5 过渡话术

禁止记录腔。应用自然衔接（多版轮换），例如「好的，那我们进入下一个问题。」「行，那我们继续。」学科题/编程提交后同样只过渡、不宣判对错。

### 2.6 跑题检测与纠偏

引擎对作答做 **LLM 优先 + 关键词启发式兜底** 的跑题检测。跑题时不推进，先打断纠偏。

### 2.7 轨道与岗位（当前可选范围）

| 选项 | 状态 |
| --- | --- |
| 岗位：研发岗 | **可选** |
| 岗位：产品 / 运营 / 算法 | 可见，暂不可选 |
| 风格：压力面 | **可选**（开场不提「压力面」） |
| 风格：平和面 / 随机 | 可见，暂不可选 |
| 轨道：业务面 | **可选** |
| 轨道：HR终面 | **可见但暂不可选** |

### 2.8 核心能力一览

| 能力 | 做法 |
| --- | --- |
| 简历驱动开场 | 粘贴或上传；后台结构化；深挖短前置锚定项目 |
| 语音面试 | Edge TTS + 点击麦克风 SpeechRecognition |
| 全场一致性 | 每答抽取事实 vs 简历/介绍/历史答；立刻挑战；`inconsistencies` 耐久 |
| 诚信与控场 | 回复库编造可直接结束；挡薪资八卦；空泛最多一次短探 |
| 学科题复盘 | 当场不判；终局对照标准答案合理打分 |
| 编程环节 | 提交后中性过渡；对错仅复盘展示；弱出口不宣传 |
| 复盘报告 | 六维 + 一致性按严重度 + 编程跑测 + PDF |

**刻意未做**：完整账号/DB、扫描件 OCR、付费数字人、外部题站、流利度评分、解锁 HR/平和面。

### 2.9 本地与远端（ops）

主协作仓走 Cursor Origin（`origin`）。用户侧已成功把本仓同步到 GitHub remote `github` → https://github.com/czeyu3483-cloud/AI-（Windows 上可用 `\\wsl$\…` 路径 `git pull origin main` 后再 `git push github main`，规避 WSL→GitHub 网络不稳）。

## 3. 版本迭代记录

早期从挑战 Todolist 与架构文档起步，搭 Next.js 本地 MVP，再补语音与数字人、回复库、业务面/HR 轨道拆分、简历冲突挑战、作答时限与 intro 卡死修复。

**本迭代（全场一致性 ship + 姓名挑战加固，已对齐当前代码）**：

- **全场一致性流水线**：每答推进前对照简历全字段（姓名/学校/专业/时间/公司/职位/项目名称/项目角色/技能/GPA/奖项/数字排名）+ 自我介绍全文 + 历史作答；高/中严重度冲突立刻打断；追加会话耐久 `inconsistencies`；终局按严重度汇总
- **姓名错位 bug 根因与修复**：早期抽取漏检简历 `姓名：` / 口述「我是X」+ LLM 把硬冲突软化为 level4「仅记报告」，导致「张三 vs 李四」可滑过；现已加固——启发式必抽姓名、本地再核、高严重度（尤其姓名）**永不 defer**，自我介绍与后续每答推进前强制打断
- **近邻实体去误报**：职位等字段用核心实体归一（如「前端开发实习」≈「前端实习」），减少同义近邻误挑战
- **自我介绍**：不完整最多 1 次短探后必须 advance；全文合并落盘 `selfIntroText` 供后文比对
- **控场与话术**：开场不告知题量；话术多版轮换；深挖短前置「我看你的简历，我想问…」（禁止长篇「结合自我介绍」）
- **学科题 / 编程**：当场不宣判对错；合理评分与跑测结果只进终局复盘；开场/主 UI 不宣传「可以不编程」（编程页仅极弱「继续下一环节」）
- **轨道**：业务面 = 自我介绍 + 深挖×2 + 学科 + 编程；HR终面界面可见但暂不可选
- **远端**：用户已打通 GitHub `github` remote 同步（见 2.9）

未回归项仍成立：点按麦克风、诚信终局、不评流畅度、人像不晃。

## 5. AI 工具使用

| 工具 | 阶段与用途 |
| --- | --- |
| **Cursor / Cloud Agent** | 架构落地、FSM/API/页面迭代、一致性流水线、文档 |
| **DeepSeek** | 简历结构化、一致性抽取比对、话术润色、跑题判断、复盘 |
| **Edge TTS** | 面试官语音播报 |
| **浏览器 SpeechRecognition** | 候选人作答转写 |

开发策略：「规则在代码里、文案在模型里」——追问预算、一致性打断、诚信终局、编程不宣判由引擎决定，模型只在允许动作内润色。
