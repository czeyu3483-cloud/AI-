# 产品备忘录 · 仿真 AI 模拟面试官

**产品**：浏览器内可跑的研发岗模拟面试 Demo（默认校招/实习深度预期）  
**闭环**：脱敏简历 → 语音对练（业务面）→ 结构化复盘 / PDF  
**定位**：比「对着 ChatGPT 自问自答」更像一场会被追问、会被质疑的真实业务面。

**当前主路径（业务面）**：自我介绍 → 简历深挖×2 → 学科专业题 → 编程题（同学可选择本次不练、继续面试）→ 终局复盘。

---

## 1. 目标用户与核心痛点

**目标用户**：正在准备大厂/互联网校招或实习研发一面的本科生与近期实习候选人。他们通常有一份写满项目的简历，却很少有机会被「像面试官一样」压着问细节。

本轮迭代把产品负责人当作持续访谈对象，结合试跑与改需求，沉淀出几条比「找不到人对练」更可执行的痛点：

1. **没有真实感的追问者**。同学互问或自己对着模型练，题往往一轮一答；不会抓住「你简历写了 P95 从 800ms 到 200ms」继续问口径、验证方式与个人边界。
2. **简历与口述不一致几乎不被挑战**。候选人夸大职责、指标或技术栈时，通用对话助手倾向于顺着写；真实面试官会停下来核实，甚至因诚信问题提前结束。
3. **空泛回答被轻轻放过**。说「负责后端」「做了优化」却给不出步骤与结果时，需要一次短探后换题并打标，而不是无限追问「再详细一点」。
4. **语音交互本身会破坏沉浸感**。自动拾音误触发、人像乱晃、开场自称「模拟/压力面」、答完不知何时提交——都会让人立刻出戏。
5. **反馈若含「流利度」等与内容无关的维度，可信度下降**。候选人更想知道：技术深度够不够、项目是否站得住、下一句该怎么改。
6. **有人只想先走完面试体验，不一定本场就练编程题**。产品需要保留编程环节，同时允许同学选择「本次先不练这道题 / 继续面试」（复盘记「本次未练」，不记硬性失败）——这是体验分流，不是「随便跳过训练」的轻佻设定。

因此 MVP 收敛为：**研发岗 · 压力面风格 · 业务面轨道**——用状态机 + 简历锚定题，把「被追问 / 被质疑 / 拿到可执行复盘」做成一条可复现主路径。

## 2. 产品设计说明

### 2.1 业务面流程（当前）

共 **自我介绍 + 约 4 主问题**（配置 `questionsPerSession: 5`）：

| 环节 | 内容 | 关键口径 |
| --- | --- | --- |
| 0 · 自我介绍 | 「先做个简单的自我介绍…」 | 落盘 `selfIntroText`，后续深挖可结合介绍里点到的项目/公司 |
| 1–2 · 简历深挖×2 | 自然点名简历项目/公司/技能 | **不问简历已写清的事实**（如「用了什么框架」）；追问 **WHY / 规模 / 职责 / 失败与边界** |
| 3 · 学科专业题 | 题库随机：高等代数 / 线性代数 / 概率论 / 数理统计 / 微积分 | **当场不判对错**；标准答案与评判标准只进终局反馈 |
| 4 · 编程题 | 编辑器手写 JS + 跑测 | 同学可选择 **本次先不练这道题 / 继续面试**（原因：有人只想完整体验面试流程） |

开场口语说明大致结构（不提「压力面/模拟」元信息）：先自我介绍，再约 4 题（项目深挖、专业题、编程；本次不想练编程也可先不练、继续面试）。

### 2.2 简历接地气提问（示例）

**宜问（点名简历，挖 WHY / 规模 / 职责）**

- 「你简历里写了做过『校园二手交易平台』，我注意到上面写到 Next.js、PostgreSQL——**为什么选它，而不是 Vue？数据量大概多大**，列表/状态这类难点你怎么处理的？」
- 「再围绕简历上的『监控告警中台』往下挖：**哪个模块是你个人真正负责的？** 出过错或失败方案吗，你怎么收的？」
- 「我看你的简历里有提到在某某公司实习过……担任某某角色时，**最关键的一次技术或方案取舍是什么？为什么这么选？**」

**不宜问（复述已写事实）**

- 「你这个项目用了什么框架？」（简历已写清技术栈时）
- 「你会什么语言 / 什么技术栈？」（简历技能栏已列明时）

深挖题干在自我介绍结束后会用介绍细节做 enrichment，避免与简历/口述脱节。

### 2.3 过渡话术

禁止记录腔：「我先记下了」「我记录一下」「记下了你的回答」等（红线词表 + 润色政策）。

**应用自然衔接**，例如：

- 「好的，那我们看下一个问题。」
- 「嗯，好，那接下来这个问题。」
- 「行，那我们继续。」
- 「好，我们往下看。」

学科题作答后同样只过渡、不宣判对错。

### 2.4 跑题检测与纠偏

引擎对作答做 **LLM 优先 + 关键词启发式兜底** 的跑题检测。跑题时**不**当作完整作答推进，先打断纠偏拉回题目。纠偏脚本示例：

- 「我打断一下，我问的是{焦点}，你能围绕这个再具体说说吗？」
- 「你这个回答好像有点偏了，我想了解的是{焦点}，你能重新说一下吗？」
- 「不好意思打断一下，我们回到刚才那个问题，我问的是{焦点}。」

焦点从题干抽取（自我介绍 / 项目名 / 专业题原文摘要等）。自我介绍允许谈兴趣，不算跑题；问项目却大谈爱好/八卦且无经历锚点，或问专业概念却完全不沾知识点，会触发纠偏。

### 2.5 轨道与岗位（当前可选范围）

| 选项 | 状态 |
| --- | --- |
| 岗位：研发岗 | **可选**（Demo 主路径） |
| 岗位：产品 / 运营 / 算法 | 可见，暂不可选 |
| 风格：压力面 | **可选**（开场不提「压力面」字样） |
| 风格：平和面 / 随机 | 可见，暂不可选 |
| 轨道：业务面 | **可选** |
| 轨道：**HR终面** | **可见但暂不可选**（题库与权重代码保留；首页与 start API 锁定业务面） |

### 2.6 核心能力一览

| 能力 | 做法 |
| --- | --- |
| 简历驱动开场 | 粘贴或上传 txt/docx/pdf；后台结构化，不展示 AI 预览；深挖题锚定项目与技能 |
| 语音面试 | Edge TTS 播报面试官；浏览器 SpeechRecognition；**点击麦克风**开始/结束作答 |
| 压力业务面 | 参数化追问上限、卡壳提示 L1–L3、限时作答；中立白板，不当场宣判录用 |
| 诚信与控场 | 回复库命中编造/乱写可直接结束；挡薪资八卦与「过不过」；空泛最多一次短探 |
| 简历冲突 | 冲突探测 + 分级挑战；复盘对诚信维度降权，避免「空壳高分」 |
| 学科题复盘 | 对照标准答案要点与评判标准启发式打分，写入技术正确性备注与分题证据 |
| 编程环节 | 可手写跑测；选择本次不练时复盘标「本次未练」，不记硬性失败 |
| 复盘报告 | 六维强弱/风险 + 证据摘录 + 可执行建议；可下载 PDF |

**刻意未做（及原因）**

- **完整账号 / 持久化数据库**：本地 session + 文件日志即可演示闭环；登录会拖垮交付。
- **扫描件 OCR**：只做文本型 PDF/Word；失败回退粘贴，避免解析黑洞。
- **情绪/表情 API、付费实时数字人**：用静态真人感头像 + 说话态切换；成本与延迟不适合 MVP。
- **完整 LeetCode OAuth / 在线判题平台**：业务面内嵌可手写可跑测的小题即可，不做题站对接。
- **多岗位 / 平和面 / HR 终面解锁**：UI 保留占位并标「暂不可选」；HR 题库与权重代码保留，但选择与 start API 锁定业务面，防止半成品轨道稀释主路径。
- **流利度评分**：已从反馈中移除——口语 ASR 噪声大会误伤，且与「简历是否站得住」无关。

差异点不靠「又一个聊天框」，而靠：**题库与 FSM 可校验、追问有预算、诚信可终局、复盘有证据**。

## 3. 版本迭代记录

早期从挑战 Todolist 与架构文档起步，搭 Next.js 本地 MVP：选岗、简历、DeepSeek 润色/复盘、mock 降级。随后补上语音与数字人形象，但自动 ASR、开场书面腔、「压力面」字样、人像晃动等问题在试跑中立刻暴露，于是改为口语开场模板、静态头像、**点击麦克风**提交。

为控场稳定性引入回复库（候选人场景 1–30 原样播报；一度扩到 100 又回退，避免未确认话术进主路径），并加上全局政策：离题、思考等待、啰嗦换题、诚信结束。修 ASR 竞态与「诚信结束却反馈虚高」后，反馈改为更诚实的强弱标注。

接着拆出业务面 / HR 终面轨道与合格面试官能力框架（测什么、怎么追、怎么提示、怎么打分）。试跑发现主路径仍应做深业务面，**HR 改为可见但暂不可选**，与岗位/风格锁定同一模式。再往下加强简历冲突挑战、阶段化题序、作答软硬时限，并收紧冲突启发式，减少误杀式诚信结束。全程未回归：点按麦克风、诚信终局、不评流畅度、人像不晃。

**本迭代（intro + 4q · 面试官政策收紧）**：业务面定稿为 **自我介绍 → 简历深挖×2 → 学科专业题库（高等代数/线性代数/概率论/数理统计/微积分）→ 编程**；深挖结合简历与自我介绍，禁止复述已写事实，追问 WHY/规模/职责；过渡禁用「我先记下了」类记录腔；学科题当场不判对错，终局对照标准答案；编程提供「本次先不练 / 继续面试」（服务「只想体验面试」的同学）；补强跑题检测与打断纠偏脚本；首页轨道文案与引擎/政策口径对齐。未回归项仍成立。

## 4. 下一步设计（若再有约一周）

1. **更深的简历接地气提问**：按项目图谱生成可复现追问树，少用通用题；继续用自我介绍细节 enrichment。
2. **编程轮体验**：更清晰的题面、超时与部分分反馈；保持「本次可不练、继续面试」分流，仍不接外部题站。
3. **有条件解锁 HR / 平和面**：在业务面稳定后再开，并单独校准软性问题话术。
4. **冲突等级标定**：用标注集调误报/漏报，区分「说不清」与「在编造」。
5. **学科题评分校准**：标准答案对照从启发式走向更稳的要点命中 / LLM 辅评。
6. **轻量分析**：本场追问次数、空泛次数、诚信触发、跑题纠偏次数等，服务候选人复盘而非运营大盘。

## 5. AI 工具使用

| 工具 | 阶段与用途 |
| --- | --- |
| **Cursor / Cloud Agent** | 架构落地、FSM/API/页面迭代、回归修复、文档与备忘录撰写；按产品反馈快速改交互与评分口径 |
| **DeepSeek** | 简历结构化与摘要、面试官话术润色（受轨道/政策约束）、跑题相关性判断、复盘维度与建议；无 Key 时 mock 可演示 |
| **Edge TTS** | 面试官语音播报，配合头像说话态 |
| **浏览器 SpeechRecognition** | 候选人作答转写；与点击麦克风状态机配合，避免自动拾音抢话 |

开发策略是「规则在代码里、文案在模型里」：追问预算、诚信终局、换题条件、跑题纠偏、学科题不宣判由引擎决定，模型只在允许动作内润色，避免自由发挥毁掉产品边界。
